## 悬浮底栏与玻璃（0.1.44）

- 底栏是自己画的悬浮胶囊（`components/tabChrome.tsx`），离屏幕两边 16、离系统手势条 10，高 64。往下滚缩成左下角 64 宽的小胶囊，只剩当前页图标；往上滚、滚回顶部、点它、换页都会展开。同一方向累计滚过 32 才触发（慢慢推也能缩），每个页面各记各的滚动位置。动画是形变不是切换（0.1.46）：玻璃壳拆成左帽、中段、右帽，中段 scaleX 收到 0、右帽左移，整条连续缩成圆；当前页图标从自己的格子滑到圆心、全程不消失；其余项往圆心收 40% 并在前 35% 进度里淡出（展开时最后才浮现）。弹簧驱动（stiffness 320、damping 32，插值 clamp 掉回弹），中途反向从当前位置掉头。只动 transform / opacity，原生驱动。壳的三块用实色 `glassSolid`，整组统一降到 `glassAlpha`（离屏合成），两个帽各多伸 4 的平直部分盖住中段两头，拼缝不露线；底栏不用阴影。换 Tab 时选中底块弹簧滑过去。缩起时只有圆接点击，展开时只有各项接点击。
- 「问一句」固定在底栏上方，底栏缩起时不往下落（0.1.45：落下去正好占了原来「运动」的位置，容易误点）。标记带点，不然像加载圈。
- 玻璃只给悬浮的控件（底栏、问一句）；卡片、数字、图表一律实底，保证读数清楚。安卓没有系统液态玻璃，用仿玻璃：`colors.glass` 半透明底 + `glassBorder` 细亮边 + 阴影（`glassStyle`），不做真模糊（不加 `expo-blur`）。
- 当前页：图标和字用正文色、加粗，底下垫一块 `border` 色的圆角；其余次要色。
- iOS 移植时换成 expo-router 的原生 Tab（`unstable-native-tabs`），直接用系统液态玻璃和下滑收小，不再自己画。
- Tab 页的内容底部多留出底栏 + 问一句的高度，最后一行不被盖住。

## 主题（0.1.44）

- 设置里「外观」三选一：跟随系统（默认）/ 浅色 / 深色，存在本机。
- 颜色在 `theme.ts` 里成对：`dark` 和 `light`；`colors` 是当前那套，换主题时原地换，再把导航树重挂一次（`ThemeProvider`），停在当前页。新颜色一律两套都写，不在视图里写死（运动页判断色块上的白字除外）。
- 模块顶层的 `StyleSheet` 用 `themed()` 包，读的时候按当前主题重建。
- 浅色里判断色、仪表色换成白底上压得住的深一档；运动页判断色块不变。
- 启动画面和窗口底色仍是深色（原生资源，没跟主题走）。

## Agent（0.1.37 起）

每页从上往下四层，顺序固定：

1. **它说的那句**（`AgentVoice`）：「环与点」小标记 + 橙色小字「看了你 X 日的数据」+ 大字结论（`font.display`，粗）+ 一两句补充（`textSoft`）。文案在 `lib/agent.ts`，口吻按 PRD §9.1。
2. **我看到的数**（`Evidence`）：一排标签，数加粗、单位跟着数，灰字放日期、区间、基线。能点的进趋势。缺的数用虚线框、灰字写缺（「恢复分 · 手表没给」）。出手表范围的数用黄。
3. **把握**（`ConfidenceRow`）：三格，亮格用橙；后面一句原因和办法（`confidenceTip`）。把握高时只写「把握高。」。运动页放在判断下面；睡眠、日常两页暂不放。
4. **你怎么回**：运动页三个按钮；三页右下角同一颗「问一句」（`AskButton`），浮着，不进底栏。点开是面板：先列这一页我看到的数（本地拼，不请求模型），问答下一版接上。

- 橙色只给 Agent：标记的色带、橙色小字、把握亮格、「问一句」的描边。当前 Tab、选中的筛选项和按钮改用正文色（铺正文色底、深色字）。例外仍是设置页实心「连接 COROS」。
- 运动页的判断贴边铺满（`Screen` 的 `hero`），底色按 kind：有氧 `#1D4FB8`、强度 `#11704B`、休息 `#A3303C`、回归期 `#7A5A10`（`colors.kindField`），整句白字，不再单独涂一个词。结算出现时不铺色块。
- 标记在 24px 时点要看得见（不然像加载转圈）：点比图标里的大，外圈挖一道底色缝。
- 不把首页改成聊天。对话只是追问的入口。

## 仪表（0.1.38 起）

用户 2026-11-19 说改版后丢了仪表盘的味道，选了 E 版：Agent 那句话仍是主角，仪表紧跟在下面，是我看到的数的画法。组件在 `components/gauges.tsx`，计算在 `lib/gauge.ts`。

- 每块表的刻度只来自三处：你自己的历史（28 日基线）、手表给的区间、规则自己的门槛。不设目标值（没有步数目标）。
- 睡眠与恢复：三个 270° 弧形表，表下只写名字，不写「线 = 28 日基线」这类说明（0.1.39 用户说没必要）。表中时长一行放下，字宽时缩字不换行。睡眠 0–10 小时，短刻线是 28 日基线（和趋势页同一个 `seriesBaseline`）；夜间 HRV 只画一个点，弧上那段蓝是手表给的正常范围，两头在弧外写数（如 40、60），刻线是手表基线（平时），量程让范围占中间一半、当晚值和基线都装得下（`hrvScale`），出范围点和数字用黄；恢复 0–100，有手表判断才按判断上色。表中心大数下面一行小字：睡眠写评分（「80 分」），HRV 写「平时 55」，恢复写手表的档位（「良好」）。HRV 或恢复的数不是睡眠那一晚的，这行小字改写它自己的日期（「11 月 24 日」），不然会被当成昨夜的数（0.1.42）。手表没给 HRV 范围时，「平时」用你自己的 28 日 HRV 基线，量程以它为中心上下 40%，照样画点和刻线。缺的数轨道调暗，中间写「没有」。「今天」从醒来开始（0.1.44，`lib/dayBoundary.ts`）：今天已有一晚结束就翻天，否则到平时醒来 + 2 小时（5:00–12:00，没记录按 9:00）才翻；之前这一页、运动页、每日记录都还算昨天，也不问早上感觉。日常健康仍按日历日。0.1.40 起这一页没有「另外看到的」标签区，也没有页底的恢复说明块：手表基线、评分、恢复档位进了表，预计完全恢复几小时进了那句话的正文。「问一句」面板里仍全列。
- 日常健康：没画成表的项（活动消耗、运动分钟、血氧……）是刻度卡里的行（`MetricRow`），不再单列「另外看到的」标签区（0.1.40）；没数的项收成卡底一行灰字「还没有：步数、静息心率」（0.1.44）。24 小时压力表盘，每小时一根，长度 = 那一小时的平均压力（0–100），颜色按四段 0–25 / 26–50 / 51–75 / 76–100（`colors.stress`：深蓝、蓝、琥珀、橙，冷到暖，不用红），下面图例只写数段不写评价；没采到的小时只留短灰点，中间是日均；点表盘进压力趋势。原来每 5 分钟的压力线去掉了（日间心率有数时仍画过程线）。静息心率、步数是两条横向刻度条：静息心率的带是 28 日基线 ±5%（和规则判断偏离同一口径），升高时数字用黄；步数从 0 填到当天，刻线是 28 日平均。
- 运动：「训练仪表」卡，三个半圆表：状态值（−40…30）、负荷比（0…2）、离上次强度几天（0…14）。警戒段直接涂在轨道上（35% 透明），外圈再描一道实色细带（填充从左起会盖住轨道上的段），值落进哪一段填充就用那一段的颜色，否则测量蓝；有数就至少画 3% 的一小段（值低于量程下限时也看得见，状态值 −42 对 −40）；刻线就是 `advice.ts` 的门槛（`RULE`：负荷比 > 1.5 停、状态值 < −30 停、< −10 不上强度、满 2 天才可再上）。`gauge.test.ts` 会读 `advice.ts` 核对这几个数，改规则时这里跟着改。
- 红黄警戒段只在运动页；另外两页的表只用测量色（蓝、白、睡眠蓝），出区间用黄。橙色不进仪表（压力表盘的橙段是测量分段，不是 Agent 的橙，色值也不同）。
- 缺的数：轨道整条调暗，不用虚线（圆头虚线在小尺寸上像一串珠子）。
- 表下说明文字两行时手动断行，不让一个字掉到第二行。

## 不采用的方向

2026-11-05 对着现成界面重排过一次，这两条当时就被丢掉，不要再捡回来：

- 运动类落地页：大色块、游戏化、勋章、连续打卡。这个产品成功的样子是少打开，不是多停留。
- 养生配色和衬线标题。深底和橙色已经是这套界面的颜色，不另换一套字体（也不加字体包）。

方向色：

- 静息心率升高用暖色。这个方向对身体不好。
- 负荷比偏低用中性色（`TrendBadge` 的 `neutral`）。偏低是信息，不是故障。偏高仍用暖色。
- 没有恢复分、没有睡眠，不要用绿色卡片去说「可以上强度」。许可语等 §5.3 用本人 60 天分布校准之后，只出现在运动页的建议里。

图标用 `icons.tsx` 里的线框 SVG，线宽保持一套。不用 emoji 当图标。

## 字和间距

- 判断用 `font.metric`（22）。把握用 `font.subhead`（13），和判断第一行同一条基线（`alignItems: 'baseline'`，不要再加 `marginTop`）。
- 承载信息的字不小于 `font.footnote`（12）。`micro` / `caption` 只给非信息装饰。
- 间距用 `space`：4 / 8 / 12 / 16 / 24。触控热区 `touch` = 48。按下用透明度，不改布局。
- 圆角 `radius` = 8，筛选项和卡底按钮也是 8。环仍是圆的。
- 时长：正文写「6 小时 21 分」（`fmtHM`），环里、分期行、记录列表写「6 时 21 分」（`fmtHMShort`），数字大、单位降一级。不用「6h21m」，也不用「18:00」这类冒号写法。
- 「当前显示的是模拟数据」用次要色。「数据停在 X 日」用正文色，它比模拟数据提示更要紧。后半句「点右上角刷新」只在顶栏有刷新按钮的三个 Tab 页出现（`Screen` 的 `refreshable`），设置、趋势、详情等下一层页面只说停在哪天。
- 实心橙色按钮只有一个：设置页没连接时的「连接 COROS」。这是全 App 唯一的首要动作，算强调色规矩的例外。别处的按钮不填橙。
- 启动时的窗口底色是 `bg`，不出现白屏。
- 能点的一块，和当天的结论（建议或结算），才单独成面。本周和当月这两张图也成面，因为当月能点、两张是一对。其余用顶上的细线和空隙分开。卡里不再套一块带底色的小块，数字直接落在面上。
- 结算那句用正文色。强调色只给当前 Tab、当前筛选项、选中的按钮。

## 睡眠与恢复

默认打开这里。从上到下：Agent 那句话（「昨夜睡了 6 小时 40 分。HRV 48，比你平时的 55 低，还在你的正常范围（40–60）里。」，正文是手表的恢复原话「手表说恢复良好，预计 8 小时后完全恢复。」，再下面一个「看今天练什么 ›」链接跳运动页）、三个表、入睡起床时段和各期占比。

- 我看到的数里，睡眠、HRV、恢复分各走各的日期，不合成「昨夜」。缺的写缺，不点进去。
- HRV 那半句（`hrvPhrase`）：先报数，再和手表基线比（差 5% 以内写「和你平时的 X 差不多」，否则写高或低并带数），再说在不在「你的正常范围（下限–上限）」里，范围写出数。不说「手表区间」（2026-11-25 用户说看不懂）。出范围写「高过 / 低于你的正常范围（…）」，并加「这只是一晚，我不拿它下结论」，数字用黄。这推翻了 2026-11-10 定的「不写『高于区间』」，那条是环形图时代的。
- 各期是总分钟的比例条，不是逐段时间轴（接口没有）。清醒用橙 `#FF9F43`（`colors.sleep.awake`，2026-11-19 用户要的；和 Agent 的 `#FF6B2C` 不是同一个橙），趋势页分期条也跟着变。
- 手表给了恢复分才显示数字，文案只写「手表给出的恢复分」。
- 表下面是「今天早上感觉怎么样？」一排 1–5（两头写「很累」「很好」，中间不写字），点一格就存，不用确认；记过收成一行「早上感觉 4 / 5 · 改」，右边「看记录 ›」进每日记录页。选中铺正文色。这是你给自己打的分，不是 App 的评价，不进建议（0.1.41）。
- 这一页不下今天练不练的判决，只给一个「看今天练什么 ›」链接（Agent 色小字，`AgentVoice` 的 `action`）。许可语等 §5.3 校准，校准前也不出现在这里。

## 日常健康

## 用词（0.1.47）

一个概念只用一个词。改文案前先对这张表。

| 概念 | 用 | 不用 |
| --- | --- | --- |
| 你自己的参照（这天之前 28 天平均） | 平时；图例写一次「平时（前 28 天平均）」 | 基线、28 日基线、28 日平均、28 日平时、常态、个人基线 |
| 手表给的 HRV 参照 | 手表基线 | 平时（除非手表没给、用的是你自己的平时） |
| 手表给的 HRV 上下限 | 正常范围 | 正常区间、手表区间 |
| TSB / ACWR | 状态值 / 负荷比 | 状态 TSB、ACWR（英文缩写只在知识条目里） |
| 体能、疲劳（CTL / ATL） | 体能 / 疲劳 | 体能 CTL、疲劳 ATL |
| 一次高强度训练 | 强度课；动词「上强度」 | 高强度 |
| 值缺了 | 没有；知道原因写原因（手表没给、没采到） | 无数据、暂无…… |
| 空列表 | 还没有……。 | 暂无……。 |
| 日期 | 11 月 27 日（数字两边有空格） | 11月27日、11-27（坐标轴除外） |
| 用户回的动作 | 回、照做、没练、改成…… | 按钮、点过按钮 |
| 停训线 | 别跑、不上强度 | 停、先把账还上 |
| 结论下面的数 | 我看到的数 | 它看到的数 |

- 判断色块里，时长和区间那一行说「做什么」，下面的补充句只说「为什么」，不重复时长和区间。
- 结算卡不打分：不用「对」「还行」。
- 不把内部名字给用户看：文件名、规则、工具、token、元数据。报错写「连不上高驰，稍后再试（错误 …）」。
