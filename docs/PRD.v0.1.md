# NowORNever — 高驰第三方 App PRD（自用版 v0.1）

> 一句话定位：把高驰手表的数据，重组成“今天我该怎么练”的决策界面。

## 1. 用户

### 1.1 目标用户画像
- **谁**：有系统训练习惯的耐力运动爱好者，比如马拉松、越野、铁三。佩戴 COROS Pace 4，每周训练 4 到 7 次。
- **数据素养**：知道 HRV、静息心率、训练负荷、阈值配速是什么，但不想每天在官方 App 里翻好几层页面拼出结论。
- **当前版本只服务一个人**：产品经理本人。不考虑多账户、合规、上架。

### 1.2 不服务谁
- 只看步数、睡眠分数的轻度用户。他们用官方 App 就够了。
- 管理多个学员的教练。这个需求更适合 COROS Training Hub。

### 1.3 官方 App 的问题（差异化依据，待补充真实痛点）
1. 恢复、睡眠、HRV、负荷分在不同页面，早上要拼凑才能判断“今天练不练”。
2. 只显示单日值，缺少“和我自己的基线比”这个视角。
3. 训练建议不透明，看不出依据。

## 2. 核心场景

| 时间 | 场景 | 打开哪个 Tab | 要得到的答案 |
| --- | --- | --- | --- |
| 起床后 | 检查恢复 | 睡眠与恢复 | 今天能不能上强度 |
| 白天 | 身体有没有异常 | 日常健康 | 静息心率、压力有没有持续偏离 |
| 训练前 | 今天练什么 | 运动（顶部建议卡） | 强度、时长、心率区间 |
| 训练后 | 复盘 | 运动（单次详情） | 配速 / 心率曲线、分圈、负荷 |
| 每周 | 看能力变化 | 运动（运动能力） | 体能、疲劳、阈值、成绩预测趋势 |

## 3. 产品原则
1. **结论先行**：每个 Tab 的首屏顶部先放一句话结论，再展开数字。
2. **个人基线**：指标默认和 7 天均值、28 天均值对比，用偏离程度（↑ / ↓ / 正常）表达。
3. **可解释**：所有建议都列出触发它的依据。
4. **一屏判断**：关键判断不需要滚动。

## 4. 信息架构

底部导航从左到右：**睡眠与恢复**、**日常健康**、**运动**。

### 4.1 睡眠与恢复
线框：
```
┌──────────────────────────────┐
│ 恢复结论卡                    │
│  ● 状态良好，可以上强度       │
│  依据：HRV 高于基线 6%；睡眠 7h42m │
├──────────────────────────────┤
│ 昨夜睡眠  7h42m   23:18 → 07:00│
│ [深睡|浅睡|REM|清醒 堆叠条]    │
├──────────────────────────────┤
│ HRV 58ms ↑  静息心率 46 ↓  恢复 92% │
│ （对比 7 日 / 28 日基线）      │
├──────────────────────────────┤
│ 趋势 14/30 天：睡眠时长、HRV   │
└──────────────────────────────┘
```

### 4.2 日常健康
- 今日概览卡片：步数、活动卡路里、静息心率、压力、血氧。实际以 COROS 接口返回的字段为准，见 §6。
- 异常提示：某个指标连续 3 天偏离 28 天基线超过阈值时显示。
- 趋势：可在周和月之间切换。

### 4.3 运动
- **今日训练建议**（置顶卡片）：给出建议类型（休息 / 恢复跑 / 有氧 / 强度课）、时长、心率区间，并列出依据。
- **运动记录列表**：显示日期、类型、距离、时长、平均配速和训练负荷，可按类型筛选。
- **单次详情**：
  - 摘要
  - 配速、心率、步频曲线
  - 分圈表
  - 心率区间分布
  - 训练负荷和训练效果
- **运动能力**：
  - 体能（CTL）、疲劳（ATL）、状态（TSB）趋势
  - 最大摄氧量
  - 乳酸阈心率和阈值配速
  - 马拉松水平和成绩预测

## 5. 指标口径

| 指标 | 定义 | 基线 / 计算 |
| --- | --- | --- |
| HRV | 夜间 HRV（ms），优先用 COROS 提供的值 | 7 日 / 28 日均值；偏离 ±7% 视为显著 |
| 静息心率 | 当日最低稳定心率，以 COROS 值为准 | 比 28 日均值高 ≥ 5 bpm 视为偏高 |
| 睡眠时长 | 入睡到醒来，扣除清醒时间 | 低于 6.5h 视为不足 |
| 恢复 % | COROS 恢复值；没有时由 HRV、静息心率、睡眠合成 | 0–100 |
| 训练负荷 | 单次 COROS Training Load | 每日求和 |
| ATL / CTL | 每日负荷的指数加权平均，时间常数分别为 7 天和 42 天 | TSB = CTL − ATL |
| 负荷比 ACWR | 7 日负荷均值除以 28 日负荷均值 | 0.8–1.3 为安全区，超过 1.5 为高风险 |

## 6. 今日训练建议：规则 v1

输入：恢复状态、ACWR、TSB、近 7 天高强度课次数、日常异常信号。

1. 出现异常信号（静息心率连续偏高，或 HRV 显著下降且睡眠不足）时，建议**休息**或 30 分钟以内 Z1 活动。
2. ACWR 大于 1.5 或 TSB 小于 −30 时，建议**恢复跑**，30–40 分钟，Z1–Z2。
3. 恢复良好、近 7 天高强度课少于 2 次、TSB 大于 −10 时，建议**强度课**，阈值或间歇，Z4–Z5。
4. 其他情况建议**有氧耐力**，45–75 分钟，Z2。

每条建议都附上触发它的依据，并生成一句中文解读。

## 7. 数据通路（M1 验证结论）

详见 [`docs/coros-integration.md`](coros-integration.md)。摘要：

- **已打通的部分**：COROS 官方 MCP 服务使用 OAuth 2.1 + PKCE，支持动态注册公共客户端和 refresh token。App 可以直接授权，不需要自建后端。
- **约束**：回调地址必须是 https，所以需要一个静态中转页跳回 App。设备码授权不可用。
- **数据风险**：上游授权的权限是 `userInfo, runData`。睡眠、HRV、日常健康数据可能不在开放范围内。需要你登录后拿到工具清单才能确认。如果确实拿不到，Tab 1 和 Tab 2 要降级，比如从运动数据推导恢复信号，或者只显示已有字段。

## 8. 非功能需求
- 数据缓存在本地 SQLite，离线也能查看。打开 App 时增量同步。
- token 存放在系统安全存储中（Keychain / Keystore）。
- 不自建后端。唯一的外部依赖是一个静态 https 中转页。
